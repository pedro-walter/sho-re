# Track storage

Generated by `tools/trackdata.py` (checked against the emulator: see the experiment at the end).

## Overview

A track is not stored as one blob. The race code gets a **(course, stage)** pair; everything else is looked up from it:

```
(course, stage) --$FBC2--> section 0..23 --$FB62--> section record --> palette A, palette B, road shape, curve events, roadside objects
(course, stage) --$8F00--> tile DMA list A / B  (background / road graphics, plain ROM->VRAM DMA)
```

* `$FF060C` = course (0..3), `$FF060A` = stage (lap counter in Original mode, which is cleared after loading).
* The arcade game has 4 courses with **3, 5, 7 and 9 stages** = 24 sections. Original mode uses 7 of those 24 sections, one per rival; the other 17 are unused there.
* **Original mode picks the track with 3 words per rival** at `$8E58` (course, stage, `$C7DC` = stage x 8, the tile-list cursor). Number of laps is a byte per rival at `$FA92`: MIA FERRARU=2, JOSE ALVEREZ=2, NOBUHIKO HASEGAWA=3, FELICA PEREZ=3, HANS BRAUN=4, MARIE LEFOURE=5, KING ARTHUR=6. Nothing else is rival specific except the bike colour (`$8EF2`).

## Section records ($FB62)

Each record is 5 long pointers: `+0` palette A (13 words: copied to the CRAM shadow `$D3E0.. / $D396..` and faded in), `+4` palette B (10 words), `+8` **road shape** (`$FF0672`: entries `(start, radius, state)`, ends with a negative word), `+12` **curve events** (`$FF0602`: `(distance, shape id)` pairs, ends with `$7FFF`), `+16` **roadside objects** (`$FF066E`, see `tools/roadside.py`). The data of a section sits right after its record, in that order.

## Curve events and shape tables ($FB0E)

The road you see is not drawn from the physical `(state, radius)` list. A second stream, `$FF0602`, fires **4-5 events per lap** (fetched in the distance routine at `$9E18`, at `$9ED4`, into `$FF061E`; handler at `$F0A2`). An event id selects a *shape table*: a list of 8-byte entries `(x0, y0, x1, y1)` (4096 = 1.0) that sub_00F0A2 integrates as the bike advances (progress `$FF0738` += distance gain) to fill the per-scanline curve buffers `$FF1100 / $FF1280` that bend the drawn road. An event runs for 70-150 table steps (about 230-340 distance units) and covers several physical curves, so one table = one stretch of road (3-5 curves); the physical curve list and the drawn bends are separate data that agree only because the authors made them match. Entries `(0, 4096, 0, 4096)` are straight road; a table starts with ~20 straight steps, ends with ~10, and a pair `(0, 0)` terminates it.

## Tile graphics ($8F00)

Per (course, stage) there are two pointers, **list A** (`+0`) and **list B** (`+4`). A list is `(words, VRAM address, ROM source)` triples ending with a zero count (`sub_008C26` for the first load, `$C5A2` for later ones, executed by the DMA queue at `$F8C0`). The data is plain, uncompressed tile art that is DMAed into VRAM: the first block is always at VRAM `$66E0` (ground / road tiles of the stage), the next blocks (`$74E0..$9xxx`) are the horizon and sky pieces. The loader counter `$C7DC` advances 4 per load, so the sequence of loads is A(stage), B(stage), A(stage+1), ... (Original mode rewinds it by 8 once `$3A(a0) == 3`). Many blocks are shared between stages (e.g. `$22464`, `$242E4`, `$28C04`), so the game stores about 20 distinct tile blocks.

## Experiment: retargeting a rival

`tools/patchrom.py` writes a patched ROM (and fixes the boot checksum: the game checks the sum of words `$200..$1A4-end` against `$18E` and hangs otherwise). Patching only the three words of rival 0 at `$8E58` to `(0, 1, 8)` and to `(1, 4, 32)` and racing rival 0 (`scripts/trackshot.lua`) loads the road shape, events, objects, palette and tile graphics of course 0 stage 1 (desert, mountains) and course 1 stage 4 (beach) respectively. So **any of the 24 sections can be assigned to any rival by editing 3 words**, which is all a track randomizer needs. Lap count per rival (`$FA92`) is independent.

Open: the unused-in-Original-mode sections were not driven for a full lap (rival 0 stage 1 / 4 only for ~1000 frames, no crash or glitch), the meaning of the A/B lists' trigger, and the exact end condition `$FF060E` of the event stream.
